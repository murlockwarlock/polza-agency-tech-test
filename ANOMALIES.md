# Аномалии данных

Проверка выполнена скриптом импорта, агрегатными сравнениями JSON/CSV и сопоставлением ID, identity-полей, сайтов и телефонов. Нумерация CSV включает строку заголовка.

## `page_001.json` … `page_020.json`

- В envelope заявлено 1000 записей: 20 последовательных страниц по 50, и фактически строк тоже 1000.
- Уникальных ID и компаний только 994. Шесть строк полностью повторены на других страницах: `c_000224`, `c_000254`, `c_000263`, `c_000285`, `c_000367`, `c_000453`.
- Из ожидаемой последовательности `c_000001`–`c_001000` отсутствуют `c_000566`, `c_000646`, `c_000687`, `c_000723`, `c_000800`, `c_000848`. Число пропусков совпадает с числом подставленных дублей.
- Допустимые пропуски: rating отсутствует у 79 строк, site у 239, phone у 110. Они загружаются как `NULL`; `reviews_count` заполнен у всех.

## `review.csv`

### Структура и повторы

- Файл содержит 207 data records, а не ожидаемые примерно 200; строки 207 и 208 полностью пустые.
- Три строки продублированы полностью: строка 204 повторяет `c_001049` из строки 42, строка 205 повторяет `c_001050` из строки 117, строка 206 повторяет `c_001075` из строки 7.
- Только шесть ID напрямую совпадают с исходной базой: `c_000098`, `c_000246`, `c_000263`, `c_000425`, `c_000769`, `c_000851`. Все их поля совпадают.
- Ещё шесть компаний получили новые ID диапазона `c_900...`, хотя остальные бизнес-поля совпадают с исходными записями: `c_900006 → c_000738`, `c_900007 → c_000642`, `c_900008 → c_000229`, `c_900009 → c_000656`, `c_900010 → c_000571`, `c_900011 → c_000957`. В названиях дополнительно сняты кавычки. Они распознаны как существующие компании по нормализованным name + city + address, а оба source ID сохранены. Расхождение полей в этих парах ограничивается кавычками в названии; в `companies` остаётся вариант из более свежей выгрузки (без кавычек), исходные значения обеих версий доступны в `raw_payload`.

### Подозрительные, но структурно допустимые значения

- Город записан как `Санкат-Петербург` в строке 22, `Moscow` в строке 127 и `москва` в строке 166. Эти три однозначных alias нормализуются в `Санкт-Петербург` и `Москва` для фильтра и аналитики; исходные значения остаются в `raw_payload`.
- `https://shared-site.ru` назначен двум разным компаниям в строках 91 и 131.
- `https://ip-73.ru` в строке 16 уже принадлежит другой компании из JSON; то же верно для `https://ip-445.ru` в строке 181. Один сайт не объявлен уникальным бизнес-ключом, поэтому строки не склеиваются только по URL.
- У CSV всего 12 identity-совпадений с исходной базой: шесть с теми же ID и шесть с `c_900...`. Для «свежей выгрузки той же базы» это неожиданно низкое пересечение и требует уточнения семантики файла у источника.

## Несоответствие текста задания

В описании входных данных перечислены название, категория, город, адрес, рейтинг, отзывы, сайт и телефон. Поля email нет ни в одном JSON и нет в CSV, но в критериях отдельно указано качество «реальных, валидных email». Получить реальные email из приложенных данных невозможно; выдумывать их или автоматически собирать с сайтов без отдельного требования и правил обработки персональных данных было бы некорректно.
